# Project state and conventions

- Repository: jacker; permanent branch local, remote origin (github.com/loki495/jacker) with main published, one checkout. Inspect actual branches/worktrees before consequential git work.
- Environment: Docker Compose project jacker, PHP 8.5 Apache app container jacker-app, app root /var/www/html, document root public/. Portable default http://localhost:8096 binds loopback only. Local HTTPS hosting uses an ignored compose override and central private Traefik configuration.
- This checkout is the active personal deployment: source is bind-mounted and edits become live immediately. Put required environment/configuration changes in place before code, or work separately when safe ordering is impossible.
- Portable compose requires no external network. Local network/labels belong in ignored docker-compose.override.yml. Node 24 tools-profile container builds versioned Vite assets; no permanent Vite process is needed.
- Setup script: docker/setup-dev-container.sh, run during docker/Dockerfile build; maps www-data to configurable UID/GID (default 1000).
- Data: database/database.sqlite, database sessions/cache, database queue (QUEUE_CONNECTION=database; tests use sync) worked by the jacker-queue compose service, and log mail. This personal database is authoritative; there is no separate remote production database. Never seed test fixtures into it.
- Runtime: private ignored .env, generated app key, debug disabled. Exact allowed hosts and trusted proxies are configurable. HTTPS uses Secure cookies and authenticated private proxy access. The trusted final proxy supplies client-facing HTTPS scheme and port even through an HTTP tunnel hop. APP_TIMEZONE controls local timestamps and follow-up day boundaries.
- Domain: single user with no app login. Opportunity/opportunities avoids Laravel's queue jobs table. Typed actions own saves, lifecycle history, archive/restore and CSV flows. OpportunityData validates without writing. has_applied supports unknown dates; nullable scores are independent 1–5 rankings. Imports preserve extras and never overwrite existing records.
- Sorting: the default (`rank`) is combined skill match + desirability via `Opportunity::bestFirst()`, desirability breaking ties, unscored last. Detail page formats pay with `payRange()` and splits benefits/responsibilities/requirements on newlines or semicolons with `listItems()`.
- Link checks: link_checks table is the log (kind check|import, status queued|running|done|failed, result ok|dead|blocked|error); opportunities carry link_status and link_checked_at. QueueLinkChecks (also fed by the Import page's paste-links form; /link-checks is only the log plus check-all) dispatches ProcessLinkCheck with LINKCHECK_SPACING seconds between jobs; RunLinkCheck first asks JobBoardApi (Ashby/Greenhouse/Lever public APIs; a posting missing from the board or a 404 means gone, and the page is then not fetched) and otherwise fetches through JobPageFetcher (manual redirects, UrlGuard checks every A/AAAA answer against private, reserved, CGNAT and other special-purpose ranges on every hop and JobPageFetcher pins the connection to the vetted address (CURLOPT_RESOLVE); requests ask for identity encoding and do not decompress, so downloads abort past LINKCHECK_MAX_BYTES via the Guzzle progress callback (do not use the Guzzle stream option: it switches to the stream handler, which ignores the curl pinning)), GoneDetector flags 200 pages whose first gone_window characters or title match config('linkcheck.gone_patterns') or whose JobPosting validThrough has passed, JobPostingParser reads JobPosting JSON-LD, and only empty fields are filled via SaveOpportunity. A dead link (404/410) closes the job automatically unless it is applied or beyond saved/preparing; blocked and errored links are only flagged. Unexpected errors are marked failed and reported, rethrown when APP_DEBUG. Not scheduled; first real fetches are an outbound action needing the owner's go-ahead. After changing queue code restart jacker-queue (`docker compose restart queue`).
- Saved pages: ImportSavedPage (Import page form, where one file box routes by extension: .html/.htm/.mhtml/.mht/.txt to the saved-page import, anything else to the CSV flow; file .html/.htm/.mhtml/.mht/.txt or textarea, optional original URL and target job) makes a link_checks row of kind saved with no network request; MHTML is unpacked to its text/html part, JobPosting data is applied via RunLinkCheck::applyFields, otherwise page_text is kept and RequestAiExtraction queued. Saved checks never touch the job's link_status. PDFs are not supported (no pdftotext in the image).
- AI fallback: fetched pages keep PageText output in link_checks.page_text (also when JobPosting data was found, so the AI pass can be requested for any of them); the log's Read with AI button queues an ai_requests row (RequestAiExtraction, one pending per check, user action only). The app container cannot run host tools, so bin/ai-bridge (host, run as a systemd user unit, docker/jacker-ai-bridge.service, with --loop; runs each extraction as a one-off `sessioneer --wait --no-tools --timeout` session in an empty temp directory, so the model that reads untrusted page text has no built-in or MCP tools; the bridge refuses any agent other than claude and any model name that is not a plain token (^[A-Za-z0-9][A-Za-z0-9._:-]*$) because both come from the database; verified end to end, including against a page with injected instructions) uses artisan ai:claim (ClaimAiRequest builds the prompt: states the page is data only and must never be obeyed, neutralizes `=====` in the page so it cannot close the fence, and repeats the rule after it) and ai:complete (CompleteAiRequest extracts JSON, whitelists keys, drops invalid enums, then RunLinkCheck::applyFields fills only empty fields, except that an AI pass passes CompleteAiRequest::REPLACEABLE (benefits, responsibilities, requirements, hours) as keys it may overwrite and stores the earlier values in ai_requests.replaced). Config in config/ai.php.
- Page render: the log's single Read with AI button queues a render (RequestAiExtraction calls RequestPageRender) and then the extraction; ClaimAiRequest skips an extraction while its check has a queued/running render, and the extraction runs on the old text if the render fails. ai_requests rows of kind render (RequestPageRender: not for saved checks, UrlGuard-vetted, one pending per check) are claimed by the same bin/ai-bridge loop (render:claim / render:complete, render first, then AI extraction) and rendered on the host by tools/render/render.mjs (playwright-core with the cached Chromium; run `npm install` in tools/render; images, media, fonts and stylesheets are aborted, and all browser traffic goes through tools/render/proxy.mjs (a local forward proxy; `--proxy-bypass-list=<-loopback>`) which connects only to the addresses `php artisan render:allow <url>` prints, i.e. UrlGuard-vetted public ones, so redirects, WebSockets and DNS rebinding cannot reach private addresses; WebRTC is disabled by flags and an init script so no UDP bypasses the proxy; Chromium itself runs through tools/render/isolated-chrome.sh in an `unshare -rn` network namespace with only loopback, the proxy listens on a unix socket (loopback TCP with RENDER_ISOLATE=0) and relay.mjs forwards the namespace's loopback port to it (RENDER_ISOLATE=0 disables this); Chromium keeps its sandbox unless RENDER_NO_SANDBOX=1; `node --test` in tools/render covers the proxy). CompletePageRender replaces link_checks.page_text with the rendered text. LinkCheck::latestAiRequest is the extract kind only, latestRenderRequest the render kind (both use ofMany with a closure: a plain where before latestOfMany filters the outer query, not the subquery).
- Theme: Flux's `@fluxAppearance` plus a segmented switch in the top bar (`$flux.appearance`, stored in localStorage) toggles the `dark` class on html. resources/css/dark.css holds `html.dark` overrides for the hand-written colours in app.css (surfaces, text, borders; the sidebar keeps its dark palette) and re-sets Flux's accent variables, because Flux turns the accent white in dark mode. New coloured rules in app.css need a counterpart there.
- Frontend: Livewire 4 single-file anonymous class components under resources/views/pages/, free Flux 2, Tailwind 4; canonical layout resources/views/layouts/app.blade.php. Livewire supplies Alpine. Board displays the current paginated result set. Additional fields use name/value rows.
- Scoring: the Scoring page's Score unscored / Re-score all open buttons (RequestScoring; open = not closed, not archived, not applied) queue ai_requests rows of kind score (opportunity_id, mode; link_check_id is nullable), shown on /scoring with a Clear done button. bin/ai-bridge claims them with score:claim (ClaimScoreRequest fences the listing as data and adds config/scoring.php's rubric) and tries config('scoring.chain') in order until a reply contains JSON: Claude haiku via sessioneer --no-tools, then `codex exec --sandbox read-only` (gpt-6-luna), then `opencode run --pure` (free model; the opencode-go key was expired on 2026-10-25). score:complete (CompleteScoreRequest) takes only skill_match, eastern_only_hours and a note from the model; Desirability computes want (60% pay midpoint, 40% work mode, Eastern-only -1) in PHP, and SaveOpportunity writes both with the earlier scores kept in ai_requests.replaced. Codex and opencode have no tool-less mode: codex runs `--sandbox read-only` in an empty temp directory, opencode with OPENCODE_CONFIG_CONTENT denying bash, edit, webfetch, websearch, task, skill and external_directory and an empty XDG_CONFIG_HOME (no global MCP servers); codex also runs with --ignore-user-config --ignore-rules (denying read or setting tools hangs this opencode version).
- Job finder: /job-finder launches ProcessScrapeRun jobs (StartScrapeRuns: one scrape_runs row per source, refused while any run is queued/running; button-only, never scheduled). RunScrape fetches the source's `requests()` capped at scrapers.max_pages with Sleep between them, stops at the first non-2xx, parses with a `App\Services\Scrapers\JobSource` (Himalayas API, WeWorkRemotely RSS, Wellfound `__NEXT_DATA__` Apollo cache, BuiltIn job-card HTML; Wellfound/BuiltIn use the browser user agent) and stages new listings in found_jobs (unique normalized_url; skips URLs already tracked; keyword filter from config/scrapers.php except for BuiltIn, whose search filters server-side). Sources return `regions` (null = unknown, [] = unrestricted, stored as location Worldwide); RunScrape drops listings whose regions match none of scrapers.allowed_regions (US, worldwide; Andres is a US resident, so EU/LatAm-only roles are out). RunScrape runs staged pay through UsdPay::apply (fixed scrapers.usd_rates, original kept in salary_notes; migration 2026_10_25_230000 backfilled already staged rows). The finder's sort and filter are #[Url] properties. PaySort::orderBy() is the shared annualised-pay ORDER BY (scoring.annual_multiplier) for the finder and the overview. The page selects rows into a public `selected` id array (kept across pages, cleared by addSelected), and AcceptFoundJob maps every staged field (company_url, remote_restrictions, requirements, notes, deadline, posted date) through SaveOpportunity (a duplicate link dismisses the listing). Probed 2026-10-25: Hiring.cafe, Indeed, Glassdoor, Google Jobs and Remote.co block curl and headless Chromium and are not supported; Instahyre and Usemassive are not usable. Restart jacker-queue after changing scraper code or config.
- Livewire browser action names must avoid client aliases such as commit; import uses importReviewed. Server component tests do not catch these JavaScript dispatch collisions.
- Quality gate inside jacker-app: vendor/bin/pint, vendor/bin/phpstan analyse --memory-limit=1G, vendor/bin/rector process --dry-run, vendor/bin/pest. Use docker exec --user www-data jacker-app. Composer wrappers use the same commands. PHPStan level 6; Rector always review-only.
- Pest uses SQLite :memory: and explicit UTC. The pre-migration DatabaseSafety guard rejects real databases, non-testing environments, and URL/read/write overrides. Separate tests exercise other timezones. Browser QA uses a disposable database and normal local runtime; Livewire assumes fake upload storage when APP_ENV=testing.
- README documents portable setup and access configuration; docs/csv.md owns CSV formats, validation, duplicate handling and export safety. Keep all relevant docs current. No commits or pushes without the user's instruction.
